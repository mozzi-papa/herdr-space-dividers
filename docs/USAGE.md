# 사용법

## 실행 구조

Ghostty 같은 터미널 앱에서 수정한 Herdr 클라이언트가 기존 기본 로컬 Herdr 서버에 연결됩니다. 실제 셸·에이전트는 서버가 관리하고, 이 프로젝트는 화면 쪽 구분선과 분류 정보를 관리합니다.

현재 실행기는 `~/.config/herdr/config.toml`과 `~/.config/herdr/herdr.sock`을 사용합니다. 별도 설정 경로·이름 있는 세션·원격 머신 통합 목록을 위한 실행기는 포함하지 않습니다.

Homebrew 설치는 `herdr-div`를 실행해 주세요. 소스 빌드 설치는 저장소 폴더에서 `sh run.sh`를 실행합니다. 실행 중인 Herdr 안이라면 기본 설정의 `Ctrl+B`, `q`로 화면을 분리한 뒤 실행합니다.

실행기는 서버가 **실제로 응답하는지** 확인합니다. 응답이 없을 때(예: 재부팅 직후 소켓 파일만 남은 경우)에만 공식 `herdr server`를 시작해 저장된 세션을 복원한 뒤 접속합니다. 이미 실행 중인 사용자 서버는 종료하거나 다시 시작하지 않습니다.

> **문제가 생기면 순정 Herdr로 실행하세요.**
>
> ```sh
> command herdr
> ```
>
> `command`는 셸 함수와 별칭을 건너뛰고 공식 `herdr`를 실행합니다. 작업은 서버에 그대로 남아 있습니다. 서버 상태 확인, 재시작 순서와 주의 사항은 [README의 순정 Herdr 실행 안내](../README.md#문제가-생겼을-때-순정-herdr로-실행)를 확인해 주세요.

## 구분선 만들기

1. 구분선을 넣을 기준 스페이스를 선택합니다. 새 구분선은 그 스페이스가 속한 분류 바로 아래에 생기며, 미분류 스페이스를 선택하면 `미분류` 헤더 바로 아래(맨 앞 분류 자리)에 생깁니다.
2. `spaces` 목록 하단의 `div`를 클릭합니다.
3. 제목을 입력하고 Enter를 누릅니다. Esc는 취소입니다.

새 구분선은 **빈 분류**로 만들어지며 기존 분류의 스페이스는 옮겨지지 않습니다. 스페이스는 아래 설명처럼 드래그해서 옮깁니다. 구분선은 최대 32개, 제목은 최대 60자입니다. 빈 제목은 생성하지 않습니다. 제목 위에는 빈 줄 한 줄을 두고, 소속 스페이스는 두 칸 들여씁니다.

구분선이 하나 이상 있으면 목록 맨 위에 `미분류 · N` 헤더가 항상 표시됩니다(N은 미분류 스페이스 수이며 0이어도 표시). 미분류 스페이스도 이 헤더 아래에 두 칸 들여씁니다. 미분류 헤더는 고정 항목이라 드래그·접기·이름 변경·색상 변경·삭제가 없고, 클릭과 우클릭에도 반응하지 않습니다. 구분선을 모두 지우면 헤더 없이 원래의 평평한 목록으로 돌아갑니다. 사이드바가 너무 좁으면 버튼 겹침을 막기 위해 `div` 버튼이 숨겨집니다. 사이드바를 넓혀 주세요.

## 분류 소속과 드래그

스페이스의 이름이나 목록 순번 대신 **스페이스 ID**를 소속으로 저장합니다. 다른 공간을 추가·삭제해도 기존 분류가 밀리지 않습니다. 새 스페이스는 맨 위 `미분류` 헤더 아래에 나타납니다.

- 스페이스를 원하는 분류의 제목이나 스페이스 행으로 드래그하면 소속을 옮깁니다. 분류 안의 순서 이동은 Herdr의 기존 이동 동작과 함께 처리합니다.
- 스페이스를 **`미분류` 헤더나 미분류 스페이스 행**, 또는 **목록 마지막 행 아래의 빈 공간**에 놓으면 소속을 해제합니다. 해제된 스페이스는 `미분류` 헤더 아래에 표시됩니다. 목록이 화면을 가득 채웠거나 스크롤 중이면 빈 공간 해제는 적용하지 않으며, 마지막 행 위에 놓으면 그 분류에 그대로 들어갑니다.
- **구분선 제목을 드래그하면 분류를 통째로(제목과 소속 스페이스 전체) 옮깁니다.** 놓을 수 있는 자리는 다른 구분선 제목 바로 위(분류와 분류 사이)와 목록 맨 아래입니다. 놓을 자리에는 가로선이 표시됩니다. 소속 스페이스는 바뀌지 않으며, 접힌 분류나 빈 분류도 같은 방식으로 옮깁니다. `미분류`는 항상 맨 위에 고정되므로 그 위로는 옮길 수 없습니다. 끌지 않고 클릭만 하면 접기·펼치기입니다.
- 목록 밖으로 놓으면 드롭을 취소합니다. 기존 worktree 자식은 기존 부모와 함께 다룹니다.

## 접기·펼치기와 숫자 이동

제목을 클릭하면 해당 분류를 접거나 펼칩니다. 제목 옆 숫자는 현재 표시 기준의 소속 수입니다. 접어도 내부 셸·에이전트·서버는 계속 실행됩니다. 접기는 작업 중지나 메모리 정리 기능이 아닙니다.

구분선은 숫자 이동 대상에서 제외합니다. 접힌 스페이스도 전체 이동 순서에 포함하며, 단축키로 선택하면 해당 분류가 펼쳐집니다. 숫자 순서는 화면의 분류 순서를 따릅니다.

### Ghostty에서 ⌘1~9 사용하기

터미널과 Herdr 양쪽의 키 전달 설정이 필요합니다. 다음은 검증 환경의 선택 설정 예시입니다. 자동으로 적용하지 않습니다.

Herdr 설정에 이미 `[keys]`가 있다면 그 안에 아래 키만 합쳐 주세요. 같은 표를 중복 선언하지 않습니다.

```toml
[keys]
switch_workspace = "cmd+1..9"
```

사용 중인 Ghostty 설정 파일에는 다음 바인딩을 사용합니다. 기존 동일 키 설정과 충돌하지 않게 합쳐 주세요. 이 바인딩을 적용하면 해당 키가 Herdr에 전달됩니다.

```ini
keybind = cmd+digit_1=csi:49;9u
keybind = cmd+digit_2=csi:50;9u
keybind = cmd+digit_3=csi:51;9u
keybind = cmd+digit_4=csi:52;9u
keybind = cmd+digit_5=csi:53;9u
keybind = cmd+digit_6=csi:54;9u
keybind = cmd+digit_7=csi:55;9u
keybind = cmd+digit_8=csi:56;9u
keybind = cmd+digit_9=csi:57;9u
```

설정 파일을 백업하고 각 앱의 설정 다시 읽기를 적용해 주세요. 다른 터미널이나 사용자의 키 설정은 별도 확인이 필요합니다.

## 우클릭 메뉴

| 대상 | 기능 |
|---|---|
| div 제목 | 이름 변경, 구분선 삭제, 구분선 편집 실행 취소, 색상 변경 |
| 스페이스 | 기존 스페이스 메뉴, Finder에서 폴더 열기, 폴더 경로 복사 |
| `미분류` 헤더 | 메뉴 없음(고정 항목) |

### 구분선 색상

div 제목을 우클릭해 `색상 변경`을 고르면 기본색과 8개 프리셋(빨강·주황·노랑·초록·하늘·파랑·보라·분홍)이 나옵니다. 마지막 `직접 입력 (#rrggbb)`에서는 `#ff5555` 같은 값을 입력합니다. 형식이 틀리면 바꾸지 않고, 비워서 Enter를 누르면 기본색(테마색)으로 돌아갑니다. 색은 구분선 항목의 `color` 값으로 기존 구분선 JSON에 함께 저장하며 편집 실행 취소 대상입니다. 터미널이 24비트 색을 지원하지 않으면 가까운 색으로 보일 수 있습니다.

> **이전 버전 클라이언트와 함께 쓰지 마세요.** `color`를 모르는 0.1.1 이하 클라이언트나 예전 수정본이 같은 설정 파일을 저장하면 색 값이 지워집니다. 구분선과 소속은 유지되고 색만 기본색으로 돌아가니, 같은 설정 파일을 쓰는 클라이언트는 `herdr-div` 하나만 사용해 주세요.

div 삭제는 구분선만 제거합니다. 스페이스·셸·에이전트를 닫지 않으며, 삭제한 분류의 스페이스는 `미분류`로 돌아갑니다. 다른 분류의 소속은 바뀌지 않습니다.

하단 `menu → 구분선 복구` 또는 div 우클릭의 편집 취소로 최근 편집을 최대 20회 되돌립니다. 기록은 현재 클라이언트의 메모리에만 보관합니다. 접속을 종료하면 사라지며, 서버의 스페이스 순서 변경을 되돌리는 기능은 포함하지 않습니다.

Finder 열기·경로 복사는 **우클릭한 스페이스의 작업 경로**를 사용합니다. Finder 열기는 로컬 폴더만 대상으로 합니다. 존재하지 않는 폴더는 오류로 안내합니다. 터미널 출력에 있는 모든 일반 경로를 자동으로 클릭 가능하게 만드는 기능은 포함하지 않습니다.

로컬 실행의 경로 복사는 맥 클립보드를 사용합니다. SSH 환경에서는 기존 터미널 클립보드 전송을 사용하므로 접속한 터미널의 허용 설정을 따릅니다.

## 버전 표시와 업데이트 알림

하단 `menu`를 열면 맨 아래에 `Herdr Space Dividers 0.1.3`처럼 현재 패키지 버전이 보입니다. 공식 Herdr의 `update ready`와는 별개 항목입니다.

| 상황 | 화면 |
|---|---|
| 새 버전이 있을 때 | `menu` 옆에 ● 표시, 메뉴에 `0.1.4 업데이트 · 명령 복사`와 `릴리스 노트 열기` |
| 버전 항목을 눌렀을 때 | 지금 바로 최신 버전을 확인하고 결과(`최신 버전입니다`, `확인 실패`)를 보여 줍니다 |
| `명령 복사`를 눌렀을 때 | `brew upgrade mozzi-papa/tap/herdr-space-dividers`를 클립보드에 복사합니다. 터미널에 붙여넣어 실행해 주세요 |

- 자동 확인은 실행할 때 한 번, 이후 6시간마다 합니다. 실패하면 아무 표시 없이 다음에 다시 시도하고, 직접 확인했을 때만 실패를 알려 줍니다.
- 확인은 `curl`로 이 저장소의 최신 정식 릴리스 정보(`api.github.com`)만 조회합니다. 사용자 정보나 작업 내용은 보내지 않습니다.
- 업데이트를 자동으로 설치하지 않습니다. 실행 중인 화면 아래의 파일을 바꾸지 않도록 Homebrew 명령을 직접 실행하는 방식입니다.
- 자동 확인을 끄려면 `HERDR_DIVIDERS_NO_UPDATE_CHECK=1 herdr-div`로 실행합니다. 이때도 버전 항목을 눌러 직접 확인할 수는 있습니다.
- Homebrew 설치본과 소스 빌드 실행기(`sh run.sh`)가 버전을 넘겨 줍니다. 다른 방법으로 클라이언트를 직접 실행하면 버전 표시와 업데이트 확인이 나타나지 않습니다.

## 저장과 다른 기기

제목·위치·소속·접기 상태는 기존 클라이언트 JSON에 자동 저장합니다.

```text
~/.local/state/herdr-dev/client-shell/local-*.json
```

`XDG_STATE_HOME`을 설정하면 그 위치를 사용하며, 연결하는 서버의 소켓 경로에 따라 파일을 구분합니다. 저장 실패 시 오류를 안내하고 화면의 설정은 메모리에 유지합니다. 저장 오류가 있으면 종료 전에 해결해 주세요.

같은 맥의 같은 계정에 SSH로 로그인하여 같은 수정본과 세션을 실행하면 같은 설정 경로를 사용할 수 있습니다. 다른 맥의 별도 클라이언트로 자동 동기화하지 않습니다. 동시 편집은 마지막 저장이 우선합니다. SSH·다중 기기의 실제 동작은 현재 배포 검증에 포함하지 않았습니다.

SSH로 접속한 맥에서 Finder 열기를 실행하면 **Herdr 클라이언트가 실행되는 맥**의 Finder를 실행합니다. 휴대폰이나 접속한 다른 기기의 파일 앱을 여는 기능이 아닙니다.
