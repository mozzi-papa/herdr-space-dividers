# 업데이트와 복구

## Homebrew 설치

```sh
brew upgrade mozzi-papa/tap/herdr-space-dividers
herdr-dividers --version
```

검증한 패키지 릴리스를 설치합니다. 패키지 버전과 기반 Herdr 버전은 구분합니다. 구분 설정은 기존 JSON 경로를 유지합니다. 설치된 명령을 제거하려면 `brew uninstall herdr-space-dividers`를 사용하며, 설정 JSON을 자동 삭제하지 않습니다.

아래 스크립트 안내는 **소스 빌드 설치 전용**입니다. `update-custom.sh --rollback`으로 Homebrew 설치를 되돌릴 수는 없습니다. Homebrew 설치의 버전 선택과 복구는 해당 릴리스와 Homebrew 방식에 맞게 진행해 주세요.


## 두 종류의 업데이트

**공식 Herdr 업데이트**는 공식 실행 파일을 갱신합니다. **이 프로젝트의 업데이트 도구**는 지정한 Herdr 소스에 패치를 적용한 별도 수정본을 만듭니다. 공식 업데이트만으로 수정본에 새 기능이 자동 병합되지는 않습니다.

이 프로젝트 자체의 코드를 갱신할 때는 로컬 변경을 먼저 확인한 뒤 저장소를 갱신해 주세요. 패키지·스크립트 갱신을 자동 수행하는 백그라운드 작업은 없습니다.

## 공식 Herdr 업데이트 후

저장소 폴더에서 실행합니다.

```sh
sh update-custom.sh
```

공식 실행 파일은 `~/.local/bin/herdr`를 우선 확인하고, 없으면 PATH에서 찾습니다. 읽힌 버전의 공식 태그를 사용합니다. 태그가 없거나 패치가 맞지 않으면 중단합니다. 지금 실제 검증한 버전은 0.9.5입니다.

명시적으로 기준 버전을 선택할 수도 있습니다.

```sh
sh update-custom.sh 0.9.5
```

명령은 소스 확인, 패치 dry-run과 적용, 필수 기능 테스트 존재·실제 통과 확인, 전체 클라이언트 테스트, 빌드·포맷 검사, 별도 서버 검증, 설정 백업 순으로 진행합니다. 모두 성공한 뒤에만 실행 대상을 바꿉니다.

열린 화면은 즉시 바뀌지 않습니다. 완료 후 기본 설정의 `Ctrl+B`, `q`로 화면을 분리하고 `sh run.sh`로 재접속해 주세요. 이 과정에서 작업 서버를 종료할 필요는 없습니다.

## 상태 확인

```sh
sh update-custom.sh --status
```

`current`는 다음 접속에 사용하는 실행 파일, `previous`는 직전 실행 파일입니다. 각각의 버전과 파일 경로가 표시됩니다.

## 실패했을 때

출력된 `update-logs/.../update.log`를 확인해 주세요. 실패한 소스·출력도 해당 실행 디렉터리에 남습니다. 로그는 공개 전에 개인 경로나 프로젝트 정보를 확인해 주세요.

| 원인 | 대응 |
|---|---|
| 도구 또는 컴포넌트 누락 | Python·Rust·rustfmt·Zig·macOS 개발 도구를 준비한 뒤 다시 실행합니다. |
| 다운로드 실패 | 네트워크와 지정 버전의 공식 태그를 확인합니다. |
| 패치 문맥 불일치 | 기존 수정본을 유지하고 해당 버전에 맞춰 패치를 보수합니다. 강제 적용하지 않습니다. |
| 테스트·빌드 실패 | 로그를 보고 도구 버전이나 코드 변경을 확인합니다. 실패한 빌드를 수동으로 선택하지 않습니다. |
| 설정 백업 실패 | 저장소의 쓰기 권한과 디스크 공간을 확인합니다. |
| 재접속 시 서버 호환성 오류 | 실행 파일 전환과 서버 호환성은 별개입니다. 호환되는 클라이언트를 사용하고 작업 서버를 임의로 종료하지 않습니다. |

지원하지 않는 미래 소스를 자동으로 고쳐 주지는 않습니다. 구조 변경이 생기면 사람이 패치를 수정하고 다시 검증해야 합니다.

## 실행 파일 복구

```sh
sh update-custom.sh --rollback
```

`current`와 `previous`의 선택을 교환합니다. 직전 수정본이 없는 첫 설치에서는 복구할 파일이 없다고 안내합니다. 분류 설정은 그대로 두며, 서버나 공식 실행 파일을 교체하지 않습니다. 복구 뒤 화면을 분리하고 `sh run.sh`로 다시 접속해 주세요.

원래 공식 화면으로 돌아가려면 수정본 화면을 분리한 후 `command herdr`를 실행해 주세요. 공식 화면에서는 이 패치의 구분선을 표시하지 않습니다. 설정 파일은 별도로 남아 있습니다.

## 설정 백업과 오프라인 소스

선택된 실행 파일의 `releases/.../validation.json`에 설정 백업 위치·검증 로그·버전·해시를 기록합니다. 설정은 `backups/update-*`에 보존하며 자동 복구로 현재 설정을 덮어쓰지 않습니다.

오프라인 소스가 있다면 다음처럼 **그 버전의 공식 압축 파일**을 지정할 수 있습니다. Cargo·Zig 의존성까지 오프라인으로 준비되는 것은 아닙니다.

```sh
sh update-custom.sh 0.9.5 --source-archive "$HOME/Downloads/herdr-v0.9.5.tar.gz"
```

기본 Rust는 1.96.1입니다. 필요한 경우 `RUSTUP_TOOLCHAIN`을 지정할 수 있습니다. Zig는 `ZIG`의 실행 파일 경로 또는 PATH로 지정해 주세요. 다른 도구 버전은 별도 검증이 필요합니다.
