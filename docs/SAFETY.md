# 안전장치와 한계

이 문서는 코드에서 구현한 동작과 실제 확인한 범위를 설명합니다. 외부 보안 감사, 모든 환경에서의 무결점, 미래 버전의 호환성을 보장하는 문서가 아닙니다.

## Homebrew 바이너리 배포

배포 전에 릴리스 모드의 소스 테스트·별도 서버 검증을 실행합니다. 사용자 설치 시에는 이미 만들어진 파일을 Homebrew가 내려받고 SHA-256을 확인합니다. Rust·Zig·Python 빌드 도구를 사용자 맥에 설치하지 않습니다.

실행기는 별도 `herdr-div` 명령을 제공하고 기존 공식 `herdr` 명령·셸 시작 파일을 변경하지 않습니다. 디버그·릴리스 빌드는 기존 `herdr-dev/client-shell` JSON 경로를 함께 사용합니다. Homebrew 업데이트에서 이 설정 파일을 삭제하거나 다른 위치로 옮기지 않습니다.

Apple Silicon 실행 파일은 ad-hoc 서명을 검증하지만, 이는 유료 Developer ID 신원 확인이나 Apple 공증이 아닙니다. macOS 보안 기능을 끄는 명령을 설치 안내에 포함하지 않습니다. 배포 아카이브에는 제삼자 고지와 빌드 정보를 포함하며 로컬 사용자 경로·계정 값이 들어 있는지 검사합니다.

아래 자동 백업·실패 시 실행 파일 선택 유지 설명은 **소스 빌드 업데이트 도구**의 동작입니다. Homebrew 설치의 버전 관리는 Homebrew가 담당하며, 설정 파일 복구는 별도 수동 작업입니다.

## 소스 빌드 업데이트 중 보호하는 것

| 장치 | 동작 |
|---|---|
| 작업 서버 보호 | 사용자의 기존 서버를 자동 종료하거나 교체하지 않습니다. 검증은 별도 임시 소켓의 테스트 서버에서 수행합니다. |
| 기존 실행 파일 보존 | 새 파일을 별도 디렉터리에 만들고 검증한 뒤 실행 대상 링크를 바꿉니다. 이전 실행 파일도 보관합니다. |
| 설정 백업 | 전환 전에 클라이언트 JSON을 `backups/update-*`에 복사합니다. 배포 도구의 백업 디렉터리는 다른 사용자에게 읽기 권한을 주지 않도록 생성합니다. |
| 패치 검사 | 저장된 SHA-256을 확인하고, 먼저 dry-run을 수행합니다. 문맥을 무시하는 fuzzy 적용은 사용하지 않습니다. |
| 소스 검사 | 공식 GitHub의 지정 버전 태그에서 HTTPS로 받고 Cargo.toml의 이름·버전을 대조합니다. 압축 파일의 경로 이탈·위험한 링크를 추출 필터로 차단합니다. |
| 기능 검증 | 필수 테스트의 존재와 실제 통과, 전체 클라이언트 테스트, 빌드·포맷, 별도 터미널 검증을 확인합니다. |
| 실패 시 유지 | 패치·빌드·검증·백업이 실패하면 현재 선택을 유지합니다. 첫 설치에는 기존 선택이 없으므로 새 수정본을 선택하지 않습니다. |
| 동시 실행 방지 | 업데이트 잠금으로 두 업데이트가 동시에 실행 대상을 바꾸지 못하게 합니다. |

## 실행되거나 바뀌는 것

- `curl`로 공식 Herdr 소스를 받고 `patch`, `cargo`, `rustfmt`, `Zig`를 사용합니다. Cargo·Zig가 빌드 의존성을 받기 위해 네트워크를 사용할 수 있습니다.
- 다운로드한 소스와 빌드 스크립트는 **현재 사용자 권한으로 실행**됩니다. 샌드박스나 코드 서명 검증을 제공하지 않습니다.
- 저장소 안에 소스·로그·빌드 캐시·실행 파일·설정 백업·선택 링크를 만듭니다. 반복 빌드 시 디스크 사용량이 늘어납니다.
- 실제 수정본 화면에서 구분선을 편집하면 기존 Herdr 클라이언트 설정 JSON에 저장합니다. 설정 파일의 로컬 경로나 프로젝트 정보는 백업에도 들어갈 수 있습니다.
- 실행기는 서버가 응답하지 않을 때만 공식 `herdr server`를 새 세션으로 시작해 저장된 세션을 복원합니다. 서버는 항상 공식 실행 파일로만 시작하며, 이미 응답하는 서버는 종료하거나 재시작하지 않습니다. 소스 빌드(디버그) 수정본이 직접 서버를 시작하면 `~/.config/herdr-dev`를 사용해 기존 세션이 복원되지 않기 때문입니다.
- 문제가 생기면 `command herdr`로 순정 Herdr를 실행할 수 있습니다. 작업은 서버에 있으므로 수정본을 닫아도 유지됩니다. 자세한 순서는 [README](../README.md#문제가-생겼을-때-순정-herdr로-실행)를 참고해 주세요.
- 실제 `폴더 경로 복사`는 사용자의 클립보드를 바꿉니다. 실제 `Finder에서 폴더 열기`는 로컬 파일 앱을 실행합니다.

설정 백업은 기본적으로 다음 위치의 클라이언트 JSON을 대상으로 합니다. `XDG_STATE_HOME`이 있으면 해당 위치를 사용합니다.

```text
~/.local/state/herdr-dev/client-shell/
~/.local/state/herdr/client-shell/
```

공식 Herdr 실행 파일·셸 시작 파일·Ghostty 설정은 자동 편집하지 않습니다. 프로젝트에서 별도 상주 수집 프로세스나 원격 분석 전송을 추가하지 않습니다. 기본 제공 검증은 임시 상태 디렉터리를 쓰고, 클립보드 전송을 가상 터미널 출력으로 받아 실제 클립보드를 변경하지 않도록 구성합니다.

## 해시 검사의 의미

패치 해시는 패키지 안의 패치와 명세가 서로 일치하는지 검사합니다. 패치와 명세를 함께 바꾸는 공격을 막는 서명 체계가 아닙니다. 소스 해시와 실행 파일 해시는 검증 기록에 남깁니다. 신뢰할 수 있는 저장소·수정 내용을 확인하고 설치해 주세요.

## 복구 범위

`sh update-custom.sh --rollback`은 직전 수정본이 있을 때 실행 파일 선택만 되돌립니다. 최신 분류 설정을 오래된 백업으로 자동 덮어쓰지 않습니다. 공식 Herdr 서버 버전을 되돌리는 기능도 포함하지 않습니다.

사용 중인 설정이 손상된 경우에는 관련 클라이언트를 분리하고 현재 파일을 별도 보존한 뒤 올바른 백업을 선택해 수동 복구해 주세요. 여러 클라이언트가 동시에 저장하면 파일을 다시 덮어쓸 수 있습니다.

## 확인하지 않은 범위

검증한 Herdr 버전과 OS는 [검증 기록](VERIFICATION.md)을 참고해 주세요. 미래 버전, 다른 OS·칩, 실제 다른 맥의 SSH, 다중 기기 동기화, 릴리스 빌드의 성능·메모리 벤치마크, 외부 보안 감사는 현재 검증 범위에 포함하지 않습니다.

문제 보고에는 필요한 오류만 포함해 주세요. `backups/`, `update-logs/`, 설정 JSON을 그대로 공개하거나 커밋하지 말아 주세요. `.gitignore`로 로컬 결과를 제외하며 배포 파일은 코드·패치·문서·테스트·라이선스로 제한합니다.
